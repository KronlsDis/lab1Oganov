## 1. Цель работы

Цель лабораторной работы — изучить принципы параллельной обработки данных с использованием библиотеки MPI в языке Python, реализовать последовательное умножение матрицы на вектор и параллельные варианты вычислений с использованием механизмов передачи сообщений `Send/Recv` и коллективных операций `Scatterv/Gatherv`, а также сравнить результаты вычислений.

## 2. Постановка задачи

Требуется вычислить произведение матрицы \(A\) размерности \(M \times N\) на вектор \(x\) размерности \(N\). Результатом является вектор \(b\) размерности \(M\)

Входные данные хранятся в текстовых файлах:

- `data/in.dat` — два целых числа: сначала \(N\), затем \(M\);
- `data/AData.dat` — элементы матрицы, записанные по строкам, по одному числу на строку;
- `data/xData.dat` — элементы вектора, по одному числу на строку.

Последовательная программа записывает результат в `Results_sequential.dat`. Параллельные программы записывают результат в `Results_parallel.dat`.

## 3. Используемые средства

В работе используются Python, NumPy и mpi4py. NumPy применяется для хранения массивов и выполнения локального умножения матрицы на вектор в реализации `Scatterv/Gatherv`. Библиотека mpi4py предоставляет интерфейс к MPI.

Для запуска параллельных программ требуется установленная реализация MPI и команда `mpiexec` либо `mpirun`. Для автоматического тестирования используется pytest.

## 5. Последовательная реализация

В файле `sequential.py` реализованы функции чтения размеров матрицы, чтения матрицы и вектора, а также функция `sequential_mat_vec_mult`.

Вычисление выполняется двумя вложенными циклами. Внешний цикл перебирает строки матрицы, внутренний — элементы соответствующей строки. Для каждой строки вычисляется скалярное произведение с вектором \(x\). Полученные значения записываются в результирующий вектор \(b\).

Последовательная реализация используется как базовый вариант для проверки корректности параллельных алгоритмов.

## 6. Параллельная реализация с использованием Send/Recv

В файле `parallel_send_recv.py` реализована схема распределения строк матрицы между рабочими процессами с помощью точечных операций передачи сообщений.

Процесс с рангом 0 читает размеры задачи и рассылает их всем процессам с помощью `bcast`. Затем процесс 0 распределяет строки матрицы между рабочими процессами с помощью `Send`. Каждый рабочий процесс получает свой блок матрицы с помощью `Recv`.

Вектор \(x\) передаётся всем процессам коллективной операцией `Bcast`. После получения данных рабочие процессы вычисляют локальные части результирующего вектора. Для отправки результатов процессу 0 используется `Send`. Процесс 0 принимает сообщения с помощью `Probe` и `Recv`, размещая полученные элементы в итоговом векторе с учётом смещений.

В данной реализации процесс с рангом 0 выполняет функции координатора: читает исходные данные, распределяет их и собирает результаты. Вычисление локального произведения выполняется рабочими процессами.

## 7. Параллельная реализация с использованием Scatterv/Gatherv

В файле `parallel_scatterv.py` используется коллективное распределение данных.

Сначала процесс 0 считывает размеры матрицы. Значения \(N\) и \(M\) рассылаются всем процессам с помощью `bcast`.

Функция `auxiliary_arrays_determination` рассчитывает два массива:

- `rcounts` — количество элементов, передаваемых каждому процессу;
- `displs` — смещение начала блока в общем массиве.

В представленном алгоритме строки распределяются между процессами с рангами от 1 до \(P-1\), где \(P\) — общее количество процессов. Процесс с рангом 0 не получает строки для вычислений. Остаток от деления количества строк на число рабочих процессов распределяется по одной дополнительной строке между первыми рабочими процессами.

Матрица распределяется коллективной операцией `Scatterv`. Вектор \(x\) передаётся всем процессам операцией `Bcast`. Каждый процесс вычисляет локальную часть результата с помощью `np.dot`. Затем процесс 0 собирает части вектора операцией `Gatherv` и записывает общий результат в файл.

Использование `Scatterv` и `Gatherv` позволяет передавать процессам блоки разного размера, что важно при неравномерном разбиении матрицы.

## 8. Генерация тестовых данных

Скрипт `scripts/generate_data.py` формирует случайную матрицу и вектор заданных размеров. Для воспроизводимости генерации используется начальное значение генератора случайных чисел (`seed`).

Пример генерации матрицы из 200 строк и 100 столбцов:

```python
generate_test_data(200, 100, 42, "data")
```

В текущем варианте скрипта в блоке `__main__` задан вызов:

```python
generate_test_data(2000, 1000, 42, "data")
```

При необходимости размеры можно изменить для проведения экспериментов.

## 9. Тестирование

Для проверки подготовлен набор автоматизированных тестов `tests/test_lab.py`. Он охватывает следующие группы сценариев:

| Группа проверок | Проверяемые случаи |
|---|---|
| Чтение параметров | Корректный порядок \(N\), \(M\); отсутствующий файл; некорректное число |
| Чтение матрицы | Проверка расположения элементов по строкам |
| Чтение вектора | Проверка чтения всех значений |
| Последовательное умножение | Положительные, нулевые, отрицательные и дробные значения; матрицы разных размеров |
| Разбиение данных | Равномерное и неравномерное распределение; пустые блоки; число строк меньше числа рабочих процессов |
| Генератор данных | Создание трёх файлов; корректные размеры; диапазон значений; воспроизводимость по seed |
| MPI Send/Recv | Сравнение результата с эталонным вычислением NumPy |
| MPI Scatterv/Gatherv | Сравнение результата с эталонным вычислением NumPy |
| Запуск с одним процессом | Проверка сообщения о необходимости минимум двух процессов для Scatterv-версии |

Для MPI-интеграционных проверок предусмотрены следующие сочетания размеров и числа процессов:

| \(M\) | \(N\) | Число процессов | Назначение |
|---:|---:|---:|---|
| 5 | 3 | 2 | Один рабочий процесс |
| 6 | 4 | 3 | Равномерное распределение |
| 7 | 5 | 4 | Неравномерное распределение |
| 2 | 3 | 8 | Число процессов больше числа строк |
| 1 | 1 | 4 | Одна строка и несколько пустых блоков |
| 8 | 6 | 4 | Дополнительный случай неравномерного распределения |

Эталонное значение рассчитывается выражением `A @ x` с помощью NumPy. Результаты MPI-программ сравниваются с эталоном с допуском для ошибок вычислений с плавающей точкой.

MPI-интеграционные тесты требуют установленной MPI-реализации, доступной команды `mpiexec` или `mpirun`, а также установленной библиотеки `mpi4py`. Если эти компоненты отсутствуют, pytest пропускает MPI-интеграционные тесты, но продолжает выполнять остальные проверки.

## 10. Экспериментальное исследование производительности

Для сравнения производительности методикой предусмотрено выполнение вычислений на матрице размером \(200 \times 100\) с использованием 2, 4 и 8 процессов. Время выполнения следует измерить для последовательной версии и обеих параллельных реализаций.

Рекомендуется выполнить несколько повторов каждого эксперимента и использовать среднее или медианное время. Во всех запусках должны использоваться одинаковые входные данные. Перед измерением следует убедиться, что результаты последовательной и параллельных программ совпадают.

Ускорение вычисляется по формуле:

\[
S(P) = \frac{T_1}{T_P},
\]

где \(T_1\) — время последовательного выполнения, \(T_P\) — время параллельного выполнения на \(P\) процессах.

Эффективность параллельной реализации:

\[
E(P) = \frac{S(P)}{P}.
\]

Таблица для внесения измеренных значений:

| Реализация | Число процессов | Время, с | Ускорение |
|---|---:|---:|---:|
| Последовательная | 1 |  1.1931 | 1,00 |
| Send/Recv | 2 | 1.3004 | 0,92 |
| Send/Recv | 4 | 0.9344 | 1,28 |
| Send/Recv | 8 | 0.9087 | 1,31 |
| Scatterv/Gatherv | 2 | 0.8055 | 1,48 |
| Scatterv/Gatherv | 4 | 0.8406 | 1,42 |
| Scatterv/Gatherv | 8 | 0.8086 | 1,48 |

Фактические значения времени и ускорения в таблицу необходимо внести после выполнения эксперимента. Они зависят от процессора, реализации MPI, версии Python, размера задачи и фоновой нагрузки системы.

При анализе результатов следует учитывать, что последовательная версия использует вложенные циклы Python, а версия Scatterv/Gatherv выполняет локальное умножение через `np.dot`. Поэтому сравнение отражает не только эффект распределения вычислений между процессами, но и различие способов локального вычисления. Для корректной интерпретации это ограничение необходимо учитывать.
